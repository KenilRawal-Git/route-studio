# Route Studio — handoff notes
## Update 23 Oct 2026 — Route Studio website (GitHub Pages)
- **Repo:** github.com/KenilRawal-Git/route-studio (public), served at https://kenilrawal-git.github.io/route-studio/ . `index.html` is the same Route Studio page as the artifact (the artifact is still published too).
- **Weekly job** `.github/workflows/refresh.yml` (Mondays ~04:17 UTC, or Actions › Run workflow) runs `tools/refresh.py`:
  1. NaPTAN national CSV (naptan.api.dft.gov.uk) → `naptan/<ATCO area>.json` + `naptan/index.json` (area bbox + place names). The page picks areas from stop codes, town names and placed stops (`mapAreaStops`), so stops are found anywhere in Britain.
  2. BODS regional GTFS for `config.json` operator/regions → `bods/<region>-<route>.csv` (builder template format, timing points, NaPTAN + lat/lon, MF/SA/SU tabs, codes SCH/FO/etc.), `bods/index.json`, `bods/paths.json` (every stop each route calls at; map lines route through them — `bodsVia`). Term month and holiday dates are worked out from today.
  3. Geofabrik England .osm.pbf → `tools/build_tiles.py` → `mapdata/cell_<i>_<j>.json` 0.25° squares around every stop the routes call at (margin 1 square), `mapdata/index.json` v2 `{tiles:[{file,cell,bbox}]}`.
- **Page map data order** (`mapAutoData` → `mapCellData`): pre-built squares; on the website (not in an artifact) missing squares are downloaded live from Overpass (overpass-api.de, private.coffee, kumi; 2 requests at a time, retries) and cached in IndexedDB for 60 days; then the old named area tiles; then the embedded Colchester–Sudbury data.
- **Network notes:** the Claude workspace reaches BODS and bustimes.org, but not Overpass or Geofabrik (tunnel drops) — that's why map building runs on GitHub. bustimes.org's map data = NaPTAN positions and straight stop-to-stop lines; Central Connect's BODS data has no route shapes.
- **Bus guide** is now page blocks (`guideState.blocks`: cover, contents, route, map, fare, advert, app, back); map/fare blocks reuse the map/fare engines at 0.6 scale via an `emb` op.
- **Uploaded CSVs with blanks:** when a route number matches a BODS route, that route's own stops (from `bods/*.csv`) are matched first (`bodsRouteStops` in `mapResolve`), then the national NaPTAN areas. Route lines follow every stop the bus calls at (`bodsVia`) when the timing stops match a BODS pattern by code or by position (within 150 m, either side of the road).
- **Bus Times for any operator (website only):** stops still missing after BODS are looked up on bustimes.org (`busTimesRouteStops`): `api/services/?search=<missing stop names>` filtered to the same route number, then `api/stops/?service=<id>` (CORS-enabled; `services/<id>.json` is not). Matched by town + name (`naptanMatch`) and then by name alone on that route's stops (`routeStopMatch`), so "The Lion" without a town works. BODS route stops are only used when the file's stops actually overlap that route (route numbers repeat across operators).
- **Wrong-place guard:** after every stop-finding step `mapRejectOutliers` drops automatically placed stops that land far from both neighbours (>15 km and >6× the route's median gap) or far from the route's centre; the next step tries again, and bad remembered positions are deleted. Town-less names that read like stops ("The Street", "Village Hall") are never matched to towns nationally; they're matched only against the route's own stops (BODS / Bus Times).
- **Timetable distances:** `mapTimetableStops` gives each stop `t` (minutes along the route, from median running times). `stopPick` only accepts a name match within reach of its placed neighbour (|Δt| km + 2 km, i.e. ~60 km/h), choosing the best name then the nearest; `mapRejectOutliers` also drops stops further from a neighbour than that.
- **Make everything, step by step** (home screen): `W` in the wizard script. A project of routes goes through 1 Timetables (add a route, "+ Add another route", next), 2 Route maps, 3 Fares (or "No fares"), 4 Bus guide. Each step reuses that tool's form: `ttSnap/ttRestore`, `mapSnapW/mapRestoreW`, `fareSnapW/fareRestoreW` move the current route in and out; `W.colors` carries route colours. Steps 1–3 can download every route's PDF as one zip. `wGuideSync` builds the guide (cover, contents, Passenger Promise, then each route's timetable, map, fares; app, back) and on later visits updates those blocks in place (by `wuid`) so the user's guide edits stay. Fare blocks can carry their own fares (`b.fare`, `fareCfgFrom`).
- **Map labels:** stop labels are placed crowded-first, trying spots up to ~135 pt away (with leader lines) at three sizes (100/86/74%) before overlapping, and then where they overlap least. Stops with no town name show just the name (no comma, one line).
- **Project files:** "Save project file" (steps bar, and offered after any PDF/zip download in the steps) saves `{kind:"route-studio-project", W, guide}` as JSON (Sets kept via `__set`; caches dropped; built-in Passenger Promise image not stored). "Open a project file" on the home page restores the routes, maps, fares and guide and reopens the steps where they were saved.
